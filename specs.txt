1. PRODUCT OVERVIEW
================================================================================

Political | Map News is a comprehensive political news aggregation and financial
analysis tool that organizes current events across the political spectrum. It
combines:

- A bias-aware news aggregation system (52+ RSS sources)
- A real-time Google News search engine
- A political event detection and market impact system (GDELT + Google News RSS)
- A stock library with 5,081 tickers and 10Y daily OHLCV data
- A market analytics dashboard with 10 visualization tabs
- A news-vs-price overlay tool for correlating news events with stock movements

The app serves as both a media bias analysis tool and a market intelligence
platform, connecting political events to their potential financial impact.

4.1 HOME / THREE-COLUMN LAYOUT
───────────────────────────────
The home view shows a search bar, topic filter pills, and a three-column layout
that organizes articles by political bias:

  - Center column: Neutral/Fact-focused wire services (gray tint)
  - Right column: Conservative/Right-leaning coverage (red tint)

Each article card shows title, source, excerpt, and a "Compare Framing" button.
Hovering over an article highlights corresponding coverage in other columns.

Key features:
  - "Breaking News" button loads latest cluster of articles
  - "Columns" vs "Graph" view toggle in header
  - Load More pagination
  - Blindspot alerts when bias columns are missing coverage

  - Event Radar (🎯) — Political event detection

4.3 SEARCH (GOOGLE NEWS)
─────────────────────────
File: LiveSearch.tsx, routes/googleNews.ts

Real-time Google News search with:
  - Debounced input (400ms delay, min 2 chars)
  - Time range filter (Any time / Past 24h / Past week / Past month)
  - Recent searches (localStorage, max 5)
  - Trending topics (from breaking news clusters)
  - "Load More" pagination
  - Article cards with source, time ago, snippets

Backend proxies Google News RSS: https://news.google.com/rss/search?q=...
Time filtering via when:1d/7d/1m in RSS query. Server-side date filtering
applied as a fallback.

  - Right: Fox News, WSJ, Breitbart, Daily Wire, Newsmax, etc.

4.5 COVERAGE DASHBOARD
───────────────────────
File: CoverageDashboard.tsx

Three main sections:
  1. Overall Bias Distribution — Horizontal bar chart showing article counts
     and percentages across 5 bias categories
  2. Topic Coverage Matrix — Heatmap table (topics × biases) with cell
     intensity proportional to article count. Empty cells (red) = blindspots.
  3. Most Balanced Topics — Topics covered from all sides (lowest variance)
  4. Coverage Gaps — Topics missing coverage from specific perspectives

4.6 EVENT RADAR
────────────────
File: EventRadar.tsx, routes/events.ts

Political event detection system that:
  1. Fetches from GDELT DOC API (geopolitical events) + Google News RSS
  2. Classifies events via keyword regex into 9 categories:
     CONFLICT, TARIFF, SANCTIONS, RATE_CUT, RATE_HIKE, ELECTION,
     SUPPLY_CHAIN, POLITICAL_CRISIS, REGULATION
  3. Maps events to affected stock tickers/sectors (Event→Asset Mapping Table)
  4. Determines severity: critical/high/elevated/moderate/low (based on
     Goldstein scale approximation)
  5. Generates BUY/SELL/HOLD signals based on severity + category
  6. Auto-refreshes every 5 minutes

UI features:
  - Time range selector (3h/6h/12h/24h)
  - Category filter buttons
  - Severity filter buttons
  - Event cards with severity badges, category tags, affected tickers
  - Impact Dashboard sidebar with summary stats + sector impact

Event-to-Asset Mapping covers:
  CONFLICT → Defense (ITA, LMT, RTX, NOC), Energy (XLE), Gold (GLD)
  TARIFF → Bearish: Tech (QQQ, SMH, XLK), China (FXI)
  SANCTIONS → Uranium (CCJ, URA), Energy (XLE)
  RATE_CUT → Bullish: Growth (QQQ, XLK), Real Estate (VNQ)
  RATE_HIKE → Bullish: Financials (XLF). Bearish: Bonds (TLT)
  ELECTION → Gold (GLD), Volatility (VXX)
  SUPPLY_CHAIN → Bullish: Industrials (XLI). Bearish: Semiconductors (SMH)
  POLITICAL_CRISIS → Gold (GLD), Treasuries (TLT), Dollar (UUP)

4.7 STOCK LIBRARY
──────────────────
File: StockLibrary.tsx, routes/stocks.ts, stocks/db.ts, stocks/downloader.ts,
     stocks/batch_download.py

Browsing:
  - 5,081 tickers from global exchanges (S&P 500, NASDAQ-100, FTSE 100, DAX,
    Nikkei 225, NYSE)
  - Search by symbol or company name
  - Paginated grid (50 per page)
  - Each card shows: symbol, name, exchange, market cap, sector

Ticker Detail View (click a card):
  - SVG 10-year price chart with hover tooltip (date, close, volume)
  - Sector, industry, country, market cap badges
  - OHLCV data table (reversed chronological)
  - CSV download button

Data Management:
  - "Update All" button triggers batch download
  - Progress banner with percentage, ETA, current ticker
  - Download status polling every 3 seconds
  - Abort/stop capability
  - Confirmation modal before starting

Download Methods:
  1. Batch Download (Python yfinance) — PRIMARY
     - Spawns Python process: batch_download.py
     - Downloads 50 tickers at once (yf.download batch API)
     - Much faster than one-by-one (~15 min vs ~3 hours)
     - Supports --all, --update, --tickers, --batch-size flags
     - Writes directly to SQLite + progress JSON

  2. Smart Update (Node.js yahoo-finance2) — SECONDARY
     - Downloads full 10Y for missing tickers
     - Patches recent days for stale tickers (ones with outdated data)
     - 600ms delay between API calls to avoid rate limiting

  3. Full Download (Node.js yahoo-finance2) — LEGACY
     - Downloads 10Y history for all tickers without prices
     - One-by-one with retry logic

5. BACKEND ARCHITECTURE
================================================================================

5.1 NEWS DATABASE (news.db)
───────────────────────────
Three tables:
  sources — 52 RSS feeds with bias classification
  articles — All ingested articles (title, excerpt, url, published_at, cluster_id)
  clusters — Grouped articles about the same topic

Uses sql.js (SQLite compiled to WebAssembly) for in-memory operations with
periodic file flushing. Database saved to disk on a 1-second debounce timer.

5.2 STOCK DATABASE (stocks.db)
──────────────────────────────
Three tables:
  stock_tickers — 5,081 tickers with metadata (name, exchange, sector, etc.)
  stock_prices — Daily OHLCV data (2.5M+ rows)
  stock_meta — Key-value metadata for download status tracking

Same sql.js approach. Python batch downloader writes directly to the file
via Python's sqlite3 module (separate from Node.js in-memory instance).

5.3 RSS INGESTION PIPELINE
───────────────────────────
File: ingestor.ts

1. loadFeeds() — Seeds sources from feeds.json into DB on first run
2. ingestAll() — Fetches all 52 feeds in batches of 5 (parallel)
3. Each feed parsed via rss-parser, up to 20 items per feed
4. INSERT OR IGNORE prevents duplicate articles (by URL)
5. Scheduled every 5 minutes via node-cron

Note: All 52 feeds currently error with "Cannot read properties of undefined
(reading 'indexOf')" — this is a known issue with rss-parser compatibility.

5.4 ARTICLE CLUSTERING ENGINE
──────────────────────────────
File: clustering.ts

1. Gets all unclustered articles (cluster_id IS NULL)
2. Compares each against recent articles in existing clusters
3. Uses string-similarity library (Dice coefficient, threshold: 0.55)
4. Normalizes titles: lowercase, remove punctuation, filter words > 3 chars
5. If match found: assign to existing cluster
6. If no match: create new cluster with title as label
7. Runs after each ingestion cycle

5.5 EVENT DETECTION ENGINE
───────────────────────────
File: routes/events.ts

Dual-source approach:
  1. GDELT DOC API — Geopolitical event articles
     Query: tariff, sanctions, war, military, interest rate, fed, election, etc.
  2. Google News RSS — Political news fallback
     4 RSS feeds covering trade war, sanctions, fed rates, military conflict

Processing pipeline:
  1. fetchGDELTEvents() + fetchRSSPoliticalNews() in parallel
  2. processArticles():
     a. Dedup by normalized title
     b. classifyEvent() — keyword regex matching into 9 categories
     c. goldsteinToSeverity() — severity from estimated Goldstein scale
     d. determineSignal() — BUY/SELL/HOLD from severity + category
  3. Sort by severity score, then recency
  4. Return top 30 events with summary stats + sector impact

5.6 STOCK DATA PIPELINE
────────────────────────
Three download methods (see section 4.7 for details):

  Python Batch (batch_download.py):
    - yf.download() for 50 tickers at once
    - Direct SQLite writes via Python sqlite3
    - Progress reported to stock-progress.json
    - Spawns from Node.js via child_process.spawn

  Node.js Smart Update (downloader.ts):
    - yf.chart() for individual tickers
    - 600ms delay between calls
    - Phase 1: Full 10Y for missing tickers
    - Phase 2: Recent days for stale tickers

  Node.js Full Download (downloader.ts):
    - yf.chart() for all tickers without prices
    - Resume capability (skips existing)
    - Retry on 429 errors (3 retries, 5s delay)

5.7 MARKET ANALYTICS ENGINE
────────────────────────────
File: routes/marketAnalytics.ts

All analytics computed server-side from stock_prices table:

  Top Movers: Price comparison (latest vs 1D/1W/1M ago)
  Volume Spikes: Today's volume vs 20-day rolling average
  Heatmap: Latest price change + market cap for treemap
  Sectors: Average sector returns across 5 timeframes
  Seasonality: Monthly close-to-close returns averaged across top 200 stocks
  Correlation: Pearson correlation of daily returns (252 trading days)
  Risk/Reward: Annualized volatility (daily std × √252) vs annualized return
  Countries: Country-level aggregates from top 50 stocks per country

8. DATABASE SCHEMAS
================================================================================

NEWS DATABASE (news.db):

  sources:
    id TEXT PRIMARY KEY
    name TEXT NOT NULL
    url TEXT NOT NULL
    rss_url TEXT NOT NULL
    bias TEXT NOT NULL               -- left|lean-left|center|lean-right|right
    credibility_score REAL DEFAULT 0.5
    tags TEXT DEFAULT '[]'

  articles:
    id INTEGER PRIMARY KEY AUTOINCREMENT
    source_id TEXT NOT NULL (FK → sources)
    title TEXT NOT NULL
    excerpt TEXT DEFAULT ''
    url TEXT NOT NULL UNIQUE
    published_at TEXT
    cluster_id INTEGER (FK → clusters)
    created_at TEXT DEFAULT (datetime('now'))

  clusters:
    id INTEGER PRIMARY KEY AUTOINCREMENT
    topic_label TEXT NOT NULL
    created_at TEXT DEFAULT (datetime('now'))

  Indexes: idx_articles_cluster, idx_articles_source, idx_articles_published

STOCK DATABASE (stocks.db):

  stock_tickers:
    symbol TEXT PRIMARY KEY
    name TEXT NOT NULL DEFAULT ''
    exchange TEXT DEFAULT ''
    sector TEXT DEFAULT ''
    industry TEXT DEFAULT ''
    country TEXT DEFAULT ''
    market_cap REAL DEFAULT 0
    updated_at TEXT DEFAULT (datetime('now'))

  stock_prices:
    symbol TEXT NOT NULL
    date TEXT NOT NULL
    open REAL, high REAL, low REAL, close REAL
    volume INTEGER DEFAULT 0
    PRIMARY KEY (symbol, date)

  stock_meta:
    key TEXT PRIMARY KEY
    value TEXT

  Indexes: idx_stock_prices_symbol, idx_stock_prices_date, idx_stock_tickers_cap

9. KEY DESIGN DECISIONS
================================================================================

1. sql.js over better-sqlite3:
   Used sql.js (WebAssembly SQLite) instead of native SQLite bindings for
   simpler installation across platforms. In-memory with periodic file flush.

2. Dual database separation:
   News data (news.db) and stock data (stocks.db) use separate databases to
   avoid schema conflicts and allow independent lifecycle management.

3. Python for batch stock downloads:
   yfinance's batch download (50 tickers at once) is ~10x faster than
   one-by-one Node.js calls. Python script spawned as child process.

4. SVG over charting libraries:
   All charts rendered as inline SVG in React components. No D3, Chart.js,
   or other charting library. Keeps bundle small and gives full control.

5. No router — state-based navigation:
   Single-page app with useState flags for page visibility. Simpler than
   react-router for this use case. hideAll() pattern prevents state conflicts.

6. rss-parser `when:` filter bug:
   Google News RSS `when:` filter returns empty results. Fixed by removing
   the filter from the RSS query and applying date filtering server-side.

7. Progress JSON bridge:
   Python batch downloader and Node.js status endpoint communicate via
   stock-progress.json file, since sql.js in-memory DB can't see Python's
   direct file writes until server restart.

================================================================================
10. KNOWN ISSUES & LIMITATIONS
================================================================================

1. RSS Ingestion Errors:
   All 52 RSS sources fail with "Cannot read properties of undefined
   (reading 'indexOf')" — likely an rss-parser version compatibility issue.
   No articles are being ingested into the news database.

2. Python/Node.js DB Concurrency:
   Python batch downloader writes directly to stocks.db file, but Node.js
   sql.js has the DB loaded in-memory. Status endpoint reads from progress
   JSON as a workaround. After batch download completes, server restart
   needed to reload DB with new data.

3. Server Startup Time:
   Server takes ~30-60 seconds to start due to RSS ingestion errors for
   all 52 sources during initial load.

4. Stock Data Freshness:
   Stock prices are only as fresh as the last download. No automatic daily
   update cron job implemented yet.

5. No Authentication:
   All endpoints are publicly accessible. Rate limiting (100/min) is the
   only protection.

6. Limited Chart Interactivity:
   SVG charts have basic hover tooltips but no zoom, pan, or drill-down.

7. No Service Worker / Offline:
   App requires server connection. No offline capability or PWA features.
